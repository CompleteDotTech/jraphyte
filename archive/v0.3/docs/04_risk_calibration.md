# Executable risk and qualification contract

No production threshold is qualified by this release. Fabricated test rows verify arithmetic and trust boundaries, not model quality. Deployment requires independent labels, representative sampling, a predeclared protocol and an authorized qualification reviewer.

`qualification.evaluate_labels` evaluates the **final locked candidate-selection/resolver/constraint/threshold pipeline**, not a base classifier alone. The denominator is the number of accepted independent action groups. It computes the one-sided exact binomial upper error bound and accepted/eligible coverage. No accepted actions is a failure, not zero demonstrated risk. The protocol locks the threshold and pipeline fingerprint before holdout; development/calibration group overlap, duplicate action/group identities, model-origin labels and reused source groups fail.

Unique identifiers and disjoint recorded sources are necessary checks, not proof of statistical independence or representative deployment coverage. Label quality, unrecorded correlations, population shift and the timing of preregistration need external review. Multiple candidate thresholds or systems tested on the same holdout need a predeclared multiplicity/selection procedure; the CLI does not silently perform post-hoc threshold selection. Compare baselines on matched populations and matched approved risk/coverage objectives rather than raw acceptance counts.

An applicable signed qualification must exactly match task, predicate, population, candidate generator, pinned model, installed question-program version/content, materializer, packing policy, tokenizer, resolver, policy, risk class, security scope and execution mode. It also binds dataset/protocol/pipeline hashes, confidence, upper bound, coverage, counts, expiry and drift status. Synthetic mode and the unmeasured byte-estimate tokenizer cannot qualify deployment. Changing any matched dimension requires a new approved artifact. Registry revocation and issuer revocation immediately stop new automatic acceptance.

A model's raw probability, derived policy score, risk classification and authority to commit are four separate concepts. Risk floors are structural conservative classes, not empirical thresholds. Identity component expansion or dependencies can raise an operation to R5, which always requires review. Reviewed maintenance also requires review. The publication service independently verifies the exact approved artifact and the plan's external authorization under the commit lock.

Use `evaluate-labels` to produce an unsigned review artifact. Only the independent administrator/qualification process may enroll issuers and approve the result in `QualificationRegistry`. Use `audit-sample` on all automatically accepted action IDs to obtain a reproducible random review sample; reviewing only abstained cases is not a substitute. The software does not collect human labels or claim a controlled pilot has occurred.
