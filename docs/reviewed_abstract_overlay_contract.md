# Reviewed abstract overlay prototype

`trace_gc.reviewed_abstract_overlay.apply_reviewed_abstract` is an opt-in, standalone prototype. It accepts a sealed automatic assessment and returns a separate, hash-sealed reviewed result. It never modifies the automatic result, does not set graph admission, and is not wired to the 200-paper replay or field consumer.

The caller must obtain original PDF, cached page PDF, page render, native lines, converter cache, code, notation sidecar, and matching-version TeX bytes from a trusted local manifest. The review manifest binds SHA-256 of each asset and the automatic assessment hash. It contains ordered exact native spans, a complete derived diplomatic transcript, whitespace-normalized transcript, source-located closing marker, and localized corrections. A correction names the original native substring, replacement, exact TeX anchor, typed expression tree, and notation-sidecar character ID, box and embedded font hash. No global text rewrite is supported.

The cached page PDF is checked against physical page zero by a same-runtime 120 dpi rendering comparison using the existing two-channel-value tolerance for `insert_pdf` antialiasing. This rejects visibly different page content while permitting byte-distinct PDF containers; it does not establish byte-identical page structure. A `tex_anchor` is checked only as an exact substring of the bound TeX source. It corroborates reviewer evidence but does not, by itself, prove that the compiled PDF depicts the same semantic expression.

Two distinct principals must sign the identical manifest hash and decision with application-enrolled Ed25519 keys through `trace_gc.trust`. The existing `OBSERVATION` receipt purpose is used with a strict `review_kind=source-bound-reviewed-abstract-v1` payload subtype because the receipt schema has no dedicated reviewed-abstract purpose. Both issuer policies must have `can_review=True`. The current contract labels assistant reviewers as assistant; it does not claim independent human validation. `HOLD` produces no proposal. **`accepted` scientific transcription is hard disabled** with `review_acceptance_requires_complete_pdf_proof`, always before an assessment can be returned.

The separate `reviewed_legacy_proposal` decision can mark only a source-reviewed, correction-free native transcript as a complete *legacy text proposal*. It requires an explicit source `Abstract` opening, full content lines, a source `Keywords` or `Introduction` closing marker, all native glyphs accounted for, and exactly one space between source lines. It sets `math_review_required` and `notation_fidelity=HOLD` and never enables JEV or graph admission. This narrow state can be measured against the frozen legacy text98 contract while keeping scientific notation acceptance independent. It is not wired to the selected 200-paper primary path yet; private case diagnostics cannot qualify that gate.

The result explicitly reports `coverage_scope=native_text_only` and `visual_coverage_qualified=false`. A sentence present only as raster or vector drawing can be absent from native lines and notation glyph inventory, even when all native characters are accounted for. The prototype checks original-PDF page paint operations from the source heading to the closing marker and fails closed on images, unreviewed vector paths, annotations and widgets. A reviewed vector rule may pass only when the signed manifest names numerator and denominator glyphs already in the selected native spans, and the entire regenerated paint operation is one opaque, solid black horizontal stroke matching the sidecar rule's sequence, endpoints and width. For a small PDF font-box overlap, the signed manifest must also state a narrow no-visible-ink-collision review of the exact original-PDF 8x crop and bind that crop hash. A composite stroke cannot hide extra vector content. This is a geometric allowance for a native-text proposal, not acceptance of a fraction's scientific reading or its visibility under occlusion. The check can still hold legitimate figures or math marks. It cannot prove visual completeness, including unmatched text paint or PDF appearance edge cases. Therefore a legacy proposal is not a claim that every visible abstract sentence was captured. The final zero-false-proposal gate still needs source-bound review of the rendered abstract against the complete transcript. A split `1` and `Introduction` heading can close the abstract only when the number is the immediately preceding source line, both share a baseline, and their horizontal gap is bounded. The page-stamp exception requires rotated, margin-located source glyphs and stamp-only arXiv text; ordinary side-column prose cannot be excluded through that role.

The second review must have a later signed `issued_at` than the first. Reversing the receipts or issuing them at the same instant fails, so the ledger cannot present simultaneous attestations as a chronological source reinspection. This timestamp check does not prove careful reading.

The margin-stamp grammar restricts the bracket to a compact arXiv-shaped category and the optional date to month abbreviations. It rejects ordinary spaced prose, but a fabricated hyphenated phrase can still resemble a category. The page-stamp role therefore remains an attributed source-review judgment; this regex is not independent verification against arXiv metadata and cannot establish visual completeness.

Stage A now regenerates the notation sidecar and page image from original PDF bytes, requires exact replay, and partitions every sidecar character into source-spanned `used_glyph_ids` or explicitly typed `excluded_glyphs`. Every native line must have an ordered, hash-bound role, reason, bounding box and exact glyph inventory. An interleaved line between selected abstract spans or between the last span and closing marker is rejected unless it is a geometrically separate page stamp. The source-located boundary must have an appropriate line role. Bounded expression shapes (`fraction`, `script`, `accent`, `ligature`, `control`, `mapsto`) check glyph membership and available rule/relation geometry; they do not infer scientific correctness.

The result also carries deterministic `transcript_lineage` segments. Every output character is covered in order by an unchanged native substring, a hash-bound correction with its original native interval, or an explicit whitespace-only layout join. This catches an unexplained output insertion or omission inside selected spans; it does not prove that the selected spans include every visually abstract paragraph or that a correction's mathematical reading is right.

An explicit `Abstract:` or `Abstract.` prefix sharing the first content line can be excluded by exact native offsets and glyph IDs. The exclusion is accepted only when the prefix matches that source heading and all heading glyphs end before the first selected content offset. This supports the source-owned heading boundary seen in development papers without using a paper ID or reference text. It remains a HOLD-only prototype until complete abstract review is proven.

An independent code review found that the initial glyph partition could classify an omitted nonspace glyph as whitespace. The current draft rejects that role unless the source glyph is actually whitespace, with an adversarial test. The same review identified unresolved acceptance gaps: replacement text is not proved by image/typed glyphs, fraction checks do not establish horizontal scope or occlusion, cross-line expressions do not fit the current correction schema, signer timestamps alone do not prove reinspection, and caller-declared closing roles need stronger source semantics. `accepted` remains hard disabled while these are unresolved.

This **is not yet a scientific-notation acceptance implementation** for the four held historical papers: an excluded glyph's claimed role is still a reviewer attestation, and the code does not prove that every visible abstract paragraph was selected, that every scientific output token has exact glyph/TeX/image lineage, or that alternate reading orders and expression interpretations are ruled out. Cross-line fractions need further generic coverage. Its two signatures attest a manifest but do not prove that either reviewer reopened the PDF. These requirements are recorded in the private issue-19 overlay acceptance specification and must be implemented and tested before `accepted` can be enabled. No CLI or field consumer uses this module.

The authored test fixture exercises acceptance mechanics and fail-closed negatives using synthetic bytes; it is not evidence of corpus quality or scientific correctness. The interface is intentionally under review before replay integration.
